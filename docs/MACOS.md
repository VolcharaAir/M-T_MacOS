# Сборка и проверка macOS

Исходники M&T 1.5 взяты из Windows-репозитория, коммит
`63498b8d373c53b05e8a4c49e08907f4c2764875`. Общий код компилятора и интерфейса
не менялся. Добавлены упаковка macOS и проверка обеих архитектур.

## Для разработчика

Нужен Mac с полным Xcode, настроенными Command Line Tools и Flutter 3.50.1
(Dart 3.14). Версия выбрана по исходному проекту. Устанавливать новейший Flutter
вместо неё без проверки не нужно: поддержка Intel меняется со временем.
Нативные плагины проекта используют Swift Package Manager; CocoaPods может
понадобиться как резервный механизм, если Flutter сообщит об этом.

Сначала выполните из корня проекта:

```bash
bash scripts/doctor-macos.sh
```

Если Flutter отсутствует, возьмите macOS x64 SDK версии 3.50.1 для Intel
или macOS arm64 SDK той же версии для M-процессора из
[официального архива](https://docs.flutter.dev/install/archive), распакуйте
в `~/development/flutter` и добавьте `~/development/flutter/bin` в PATH.
Архитектура SDK относится к компьютеру сборки, а приложение собирается для обеих.

Xcode должен быть выбран через `xcode-select`; сначала откройте Xcode и завершите
предлагаемую первоначальную настройку. Точная команда настройки зависит от места
установки Xcode. `flutter doctor -v` показывает оставшиеся проблемы среды.

```bash
bash scripts/build-macos.sh
```

Также можно открыть `Build-MacOS.command`. При первой сборке нужен интернет для
зависимостей. Скрипт последовательно запускает анализ, тесты, проверку компилятора,
release-сборку, проверяет **каждый Mach-O файл** через `lipo` на `x86_64` и `arm64`,
проверяет подпись и создаёт `dist/MT-macOS-universal.dmg` с контрольной суммой.
Отсутствие любой архитектуры останавливает упаковку.

Приложение внутри образа — `M&T.app`. Минимальная версия проекта: macOS 12.0.
Это требование к ОС, поэтому обещание «любой Mac» на более старые ОС не распространяется.

## Проверка готового образа

1. Смонтируйте образ, перенесите приложение в «Программы» и запустите именно эту копию.
2. Отключите интернет, введите `1 -> 0` и слово `101`; обе модели должны дать `000`.
3. Проверьте `0 ->.` на `01010`: результат `1010`, одна подстановка Маркова.
4. Проверьте отдельное пошаговое выполнение обеих моделей, копирование Cmd+C,
   вставку Cmd+V, светлую/тёмную тему и изменение размеров окна.
5. Экспортируйте проект/машину через системный диалог в выбранную папку.
6. Закройте приложение и откройте вновь: проект должен восстановиться.
7. Повторите на Apple Silicon. Проверка `lipo` подтверждает наличие кода для обеих
   архитектур, но не заменяет запуск на второй архитектуре.

## Подпись и распространение

Первый пакет подписывается ad-hoc для локального тестирования, без Apple Developer.
У скачанного тестового пакета macOS может заблокировать первый запуск. Встроенная
инструкция описывает штатное разрешение через настройки безопасности.

Для распространения без предупреждения о неизвестном разработчике потребуются
сертификат Developer ID Application и notarization Apple. Этот скрипт **не** выдаёт
ad-hoc пакет за notarized-релиз. Пароли, сертификаты и ключи в репозиторий не добавлять.

## Что проверено сейчас

В Linux проверены синтаксис Bash, XML конфигурации и независимые JSON-машины.
Xcode, `flutter analyze`, Dart-тесты, выпуск `.app`/`.dmg` и запуск на Intel/Apple
Silicon в этой среде недоступны. До успешной сборки и проверки на Mac готового
установщика в Releases нет.

Официальные справочники:
[настройка Flutter для macOS](https://docs.flutter.dev/platform-integration/macos/setup),
[универсальные приложения Apple](https://developer.apple.com/documentation/apple-silicon/building-a-universal-macos-binary).
